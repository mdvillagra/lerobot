# Bagel-Robotics-1

The `bagel_robotics` policy runs and fine-tunes Bagel Labs' cp1000 checkpoint. The code uses MIT/Apache-2.0 licenses. The weights use the [Bagel Labs Research License](https://huggingface.co/bageldotcom/Bagel-Robotics-1/blob/main/LICENSE.md).

Install on Linux with CUDA and Python 3.12.

```bash
uv sync --locked --python 3.12 --extra bagel_robotics --extra training --extra evaluation
```

First use downloads and verifies the pinned model (~29 GB) and Wan encoders/tokenizer (~16.7 GB). Keep them available when loading LeRobot checkpoints. Set `--policy.local_files_only=true` for cached assets or supply `--policy.bundle_path` and `--policy.wan_model_dir` with `--policy.download_assets=false`.

## Inputs and inference

- Under `observation.images`, provide `head_camera`, `left_camera`, and `right_camera` as uint8 RGB or floats in `[0,1]`. Use `--rename_map` or set `--policy.camera_keys` in head/left-wrist/right-wrist order.
- Provide a nonempty `task` per sample. Both `observation.state` and `action` use absolute EE16 poses, left arm first. Each arm contributes `x, y, z, qw, qx, qy, qz, gripper` in the checkpoint's frames and units. Joint-position datasets such as SO-101 require conversion.
- Use one environment per policy. Call `reset()` at episode boundaries and `select_action()` every control tick to maintain camera history. It predicts 32 actions, executes 16, and blends the overlap with 90% weight on the new prediction. Changing the task resets history and seeds. For raw physical actions, `predict_action_chunk()` observes one tick and returns `[1,32,16]`. Remote chunk serving and RTC cannot supply the intervening frames.

## Fine-tune

```bash
uv run lerobot-train --policy.type=bagel_robotics --policy.device=cuda \
  --dataset.repo_id=your_namespace/ee16_demonstrations --dataset.image_transforms.enable=false \
  --batch_size=1 --steps=10000 --output_dir=outputs/train/bagel_robotics
```

Use a 25-Hz dataset. Each training sample combines the episode's first frame, eight history frames at 25-frame intervals ending at the current frame, eight future frames at four-frame intervals, the current state, and 32 actions. For manually constructed datasets, use `resolve_delta_timestamps(config, metadata)` to include the episode anchor.

By default only the video expert trains, with BF16 and gradient checkpointing. Set `--policy.freeze_action_expert=false` to train action/proprio too. Normalization uses checkpoint statistics. Training saves processors and sharded weights locally, including the frozen encoders. To fine-tune the result, set `--policy.path=/path/to/pretrained_model`.

## Export the original checkpoint

For evaluation with `--policy.path`, export cp1000 with a matching dataset's feature shapes. Use `--eval.batch_size=1` with a compatible EE16 environment.

```bash
uv run python examples/bagel_robotics/convert_checkpoint.py \
  --dataset-repo-id=your_namespace/ee16_demonstrations --output=outputs/bagel_robotics_cp1000 --device=cuda
```

CPU tests cover the native sampler and training loss with reduced experts. Full-size CUDA runs and benchmark results are pending.
